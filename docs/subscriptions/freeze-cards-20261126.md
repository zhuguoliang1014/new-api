# 订阅赠送冻结卡

功能和本地验证完成。用户已授权提交 main 并自动发布；实际部署回执在上线验收后补充。

## 行为

- 新建及编辑套餐可设置「赠送冻结卡」，范围为 0–1,000,000 的整数，默认 0。
- 充值余额不赠送冻结卡；只有购买订阅才按该套餐配置发放，未配置即为 0 张。
- 订阅在线付款和使用余额购买订阅成功时，按订单/购买快照发放。重复支付回调不重复发放；取消、过期订单的迟到支付不发放；后台直接赠送订阅不附带购买赠卡。
- 冻结卡归用户所有，跨套餐共用，不设置到期时间。已购订阅、旧订单不补发；编辑或删除目录不改变已购赠卡。
- 中国大陆法定节假日（北京时间，沿用现有日历，包含调休休息日）免费冻结，即使请求附带扣卡确认也不扣卡。
- 其他时间每次冻结有效订阅消耗一张，前端必须弹窗取得明确确认。无卡禁用冻结；后端独立校验确认参数、归属、订阅状态和余额。
- 日历未配置的年份仍可明确确认使用一张卡；界面提示日历不可用，不把未知日期认定为免费日。
- 解冻不耗卡、不退卡，到期时间及额度重置时间沿用原有顺延规则。
- 我的订阅显示可用张数；套餐卡片与两个购买弹窗显示赠卡数量。

## 数据和事务

新增字段均为整数、非空且默认 0：

| 表 | 字段 | 用途 |
| --- | --- | --- |
| subscription_plans | freeze_cards | 每次购买赠卡数量 |
| users | freeze_cards | 当前可用卡余额，不能经用户资料 JSON 修改 |
| user_subscriptions | freeze_cards_granted | 此次购买实际发放数 |
| user_subscriptions | freeze_cards_used | 此订阅累计耗卡冻结次数 |

赠卡与支付完成、订阅创建使用同一事务。扣卡与冻结使用同一事务，先锁用户再锁订阅；重复冻结不再扣卡，失败全部回滚。用户资料更新显式排除卡余额，避免旧资料覆盖并发消费。

SQLite 专用建表/增列路径及 MySQL/PostgreSQL 自动迁移均支持新字段。保留既有表和数据，不需要一次性生产补卡脚本。

接口扩展：`GET /api/subscription/self` 返回 `data.freeze_cards`；冻结请求 `PUT /api/subscription/self/:id/freeze` 在明确同意扣卡时携带 `use_freeze_card: true`。缺省不授权耗卡。

复用项目 `ConfirmDialog`、表单组件及现有套餐编辑流程。新增共享 `PlanFreezeCardsField` 承载赠卡业务字段，无新依赖。

## 后续发布与回退

发布前按现有自动部署流程备份生产库；正常部署只需增列，旧套餐默认赠卡 0。发布后按活动需要逐套餐设置赠卡张数。

回退只切应用版本，保留新增字段、余额和已购记录，不整库恢复；旧版暂停提供耗卡入口，但既有冻结订阅仍可按原逻辑解冻。重新上线后继续使用保留的卡余额。
