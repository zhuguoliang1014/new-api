# 日志 IP 归属地缓存

日志详情中，IP 后展示位置和网络，例如 `北京·电信`；查询按钮始终位于归属地内容后。消费、错误等已有 IP 行和登录日志共用同一组件，不改变 IP 的原有可见范围。

- 打开详情只请求本站 `GET /api/log/ip-location?ip=…`，读取 Redis；缓存未命中时不请求外部服务。
- 点击查询请求 `POST /api/log/ip-location?ip=…`，先复查缓存；未命中时由服务器通过 HTTPS 请求 IP9 的单 IP 接口，成功后写 Redis，保留 30 天。
- 外部接口为 `https://ip9.com.cn/get?ip=<IP>`，无需 API Key。服务说明见 `https://www.ip9.com.cn/`；支持 IPv4 和 IPv6，免费接口每个来源 IP 每分钟最多 60 次。仅 HTTP 200 且响应 `ret=200`、返回 IP 与目标相符、含有效归属信息时缓存；接口限流或失败不写入归属地，不自动重试，也不回退到旧数据源。
- 缓存键为 `ip-location:ip9:v1:<规范化IP>`，查询占位键为 `ip-location:query:ip9:v1:<规范化IP>`。旧 IPQuery 缓存和占位不再读取，无需清空 Redis；原有带 TTL 缓存自行到期。同一进程合并并发查询；Redis 的 15 秒占位跨实例抑制重复请求，并在失败后提供短暂冷却。POST 使用现有用户级关键操作限流。
- 查询服务仅接收 IP，不发送用户信息、请求内容或令牌；固定外部地址、不跟随重定向，5 秒 HTTP 超时，响应最多读取 64 KiB。内网、回环、链路本地和文档地址不可外查。
- 普通用户仅在已开启日志 IP 可见偏好时可读写自己日志中已有 IP 的缓存；管理员可查询日志中出现过的 IP。两种请求均先校验日志权限，不使用普通用户列表的展示序号定位数据库记录。查询不修改日志或数据库结构。
- IP 归属地功能仅供已登录面板使用，不接受个人访问令牌，避免用个人用量读取权限查询管理员范围的日志。
- Redis 未启用或 IP 不可外查时保留禁用按钮及原因。缓存服务故障时仍展示 IP，用户可手动重试；不会自动绕过 Redis 发送查询。
- 中国大陆 IP9 返回的中文省市合并展示，直辖市不重复名称；常见电信、联通、移动名称缩写，未知网络保留原名。国家名按界面语言展示，其他地名保留接口原文；国际 IP 展示国家及可用城市，缺失字段不补造。归属地来自第三方估算，不能据此判定个人实际位置。

2026-11-13 实际请求 IP9，`111.58.230.113` 返回中国、广西、南宁、中国移动；对应中文展示为 `广西南宁·移动`。该结果属于 IP9 数据库，与此前其他数据库返回的城市可能不同。IPv6 样例 `2606:4700:4700::1111` 返回美国、Cloudflare，省市为空，对应展示 `美国·Cloudflare`。

UI 复用 `DetailRow`、`Button`、TanStack Query 和共享 API 客户端。新增 `LogIPLocation` 只负责日志权限下的缓存状态、查询行为及内容；现有 `loading-state` 为整块加载占位，不能表达同行按钮状态，故使用既有图标与按钮组合。七份语言源文件补齐新键，运行时语言范围不变。
