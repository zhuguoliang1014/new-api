## 页面与导航建议

### 官网

顶部导航：首页、模型与价格、接入文档；右侧登录、开始使用。

| 页面 | 内容与主要动作 |
| --- | --- |
| 首页 | 服务定位、接入示例、模型入口、按量计费说明、开始使用 |
| 模型与价格 | 搜索与筛选、可用模型、计费单位与价格；登录后展示实际适用分组 |
| 接入文档 | API 地址、密钥配置、首个请求、常见错误；示例不嵌入真实密钥 |
| 支持与公告 | 现有公告、常见问题与联系方式；一期不新增工单系统 |
| 协议与隐私 | 展示已有配置内容 |
| 登录、注册、密码找回、授权回调 | 邮箱密码、GitHub、自定义认证；兼容已启用的验证要求 |

### 用户控制台

侧栏主导航：概览、API 密钥、模型、调用记录、余额与充值。底部：接入文档、账户设置。

| 页面 | 内容与主要动作 |
| --- | --- |
| 概览 | 可用额度、当日消耗、请求用量；新用户展示充值、创建密钥、接入三个步骤 |
| API 密钥 | 创建、查看与复制、编辑、启停、删除；基础字段优先，高级限制折叠 |
| 模型 | 当前用户可用模型、实际价格、模型标识与接入示例 |
| 调用记录 | 时间、模型、密钥、状态、用量、费用；详情承载完整字段 |
| 余额与充值 | 可用额度、金额选择、后端报价、支付宝支付、充值订单、待支付订单处理 |
| 账户设置 | 资料、密码、邮箱、第三方绑定、现有安全验证与会话管理 |

### 管理控制台

单独管理布局与权限入口。管理员可在用户视图和管理视图之间切换。

| 分组 | 页面与内容 |
| --- | --- |
| 运营 | 运营概览、充值订单、调用与异常日志 |
| 服务 | 渠道管理、模型管理、定价与分组配置 |
| 用户 | 用户管理、额度调整、账户状态；兑换码管理按现有使用情况纳入 |
| 设置 | 站点与公告、注册与邮箱、GitHub 与自定义认证、虎皮椒支付、必要安全配置 |

渠道支持新增、编辑、启停和测试；必要的模型映射和分组设置跟随现有后端。异常页面必须提供可追查的信息，不能只剩装饰性统计。管理员与超级管理员权限继续由后端控制。

一期不是完整复刻所有后台功能。开发前逐项盘点正在使用的配置，确认上述页面可完成现有服务的日常运营；其余后台能力后续补齐。

## 三条验收流程

1. 新用户：官网 → 注册或授权 → 充值 → 后端确认到账 → 创建密钥 → 发起真实调用 → 日志与余额反映实际扣费。
2. 回访用户：登录 → 查额度和调用异常 → 充值或调整密钥 → 继续调用。
3. 管理员：配置渠道与模型价格 → 测试并启用 → 管理用户与订单 → 查看异常、停用故障渠道。

支付覆盖待支付、支付中、到账、超时或失败、离开后回到订单等状态。跳转返回或用户点击“已支付”不能直接视为到账。金额、币种、显示额度和内部 quota 的关系根据后端接口核对，不能仅凭“1:1”把所有单位都写成人民币。

鉴权覆盖会话过期、授权取消、回调失败、已有账户绑定以及启用二次验证的账户。现有自定义 auth 具体对应 OIDC 还是自定义 OAuth provider，在接入阶段核对实际启用配置，不预先改变协议。

## 视觉提案（未锁定）

第一版的灰绿配色、代码卡片首屏与紧凑页面结构已被用户否定。用户提供了 Pipio 完整首页作为视觉参考，强调冷白空间、清晰的大标题、玻璃材质和完整长页面的节奏；不能仅做配色微调。

第二版提案：冷白背景、深蓝灰文字、清透蓝强调色。整页结构为主视觉 → 模型选择 → 调用明细 → 接入步骤 → 充值计费 → 行动入口与支持页脚。配色、布局和材质仍待用户评价。

- 官网用大标题和不对称留白，首屏用原创的多层透明透镜表达统一模型入口；代码示例移至接入区。主视觉与页面背景融为一体，避免复制参考网站的芯片和路由拓扑。
- 玻璃材质集中在导航、悬浮操作与弹窗，用边缘高光、柔和投影和背景层次表达；正文、表格和输入区域保持可读。
- 用户端采用安静的侧栏和宽内容区，关键信息直接排版，不把每个数字都包进卡片。
- 管理端沿用视觉变量，提高信息密度；筛选、批量操作、异常标记有固定位置。
- 动效围绕操作反馈，常规过渡约 160–240ms；尊重减少动态效果设置，低性能设备降级模糊效果。
- 正文对比度满足 AA；焦点可见，交互不依赖悬停或颜色；手机端侧栏折叠，关键操作不隐藏。

## 实现建议（待进入开发时确定）

- 独立 React + TypeScript 前端，共享设计变量、组件和接口适配层，三个页面区域按需加载。
- 前文提出 Vite + React Router 是独立项目方案；当前仓库 web 采用 Rsbuild + TanStack Router。新项目若放入 web 必须遵循现有目录规范；真正独立项目再确定构建与路由工具，不能直接混用。
- 使用 Bun、TanStack Query、Tailwind CSS；界面重做不依赖旧页面组件。
- 页面和文案支持国际化；设计讨论稿暂以中文呈现，正式实现遵循英文源字符串键与项目语言要求。
- 优先同域反向代理部署，落实 Cookie、刷新认证和授权回调；沿用当前后端契约，缺少必要接口时单独评估。
- 保留 new-api / QuantumNous 项目归属与许可信息。产品名称、Logo、域名尚未确定，讨论稿沿用 new-api 标识。
